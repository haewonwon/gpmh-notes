알고리즘, 자료구조, 운영체제, 데이터베이스, 컴퓨터 구조에는 이 파일을 적용하지 않는다.

# 커리큘럼 기준

이 프로젝트는 아래 Full Stack 커리큘럼의 Track C · CS 계획을 기준으로 학습한다.

https://app.notion.com/p/Full-Stack-3dc178c4afac800b891ed30b433ee075

주차별 순서, 학습 범위, 체크리스트는 위 커리큘럼을 따른다.
사용자가 현재 학습 중인 주제의 노션 페이지를 제공하면, 해당 페이지에 들어갈 학습 자료를 작성한다.

# 프로젝트 목적

네트워크를 프로토콜과 용어 암기 수준으로 학습하지 않는다.
웹 요청이 발생하는 전체 경로와 계층별 책임을 이해하여
연결 문제, HTTP 동작, 인증·보안 문제, 캐시 문제, 성능 병목을 분석할 수 있는 수준까지 학습한다.

# 페이지 작성 원칙

- 사용자가 제공한 현재 주제만 깊이 있게 다룬다.
- 페이지 내용은 교과서 챕터처럼 기초부터 논리적으로 이어지게 작성한다.
- 선수지식이 없다고 가정하고, 용어를 처음 사용할 때 정의한다.
- 단순 정의를 나열하지 말고, 왜 필요한지와 어떤 문제를 해결하는지 설명한다.
- 계층별 역할을 구분하되, 실제 웹 요청에서 각 계층이 어떤 순서로 연결되는지 함께 설명한다.
- DNS, IP, 전송 계층, TLS, HTTP, 캐시, 쿠키, 인증, 브라우저 보안 모델을 필요할 때 전체 요청 흐름 안에서 연결한다.
- HTTP 상태 코드와 헤더는 목록 암기가 아니라 서버·브라우저·중간 장비가 어떤 결정을 내리기 위한 정보인지 설명한다.
- 코드, HTTP 요청·응답, 헤더, 로그, 브라우저 네트워크 패널 등의 예시를 제시할 때 각 항목의 의미를 해설한다.
- 보안 주제는 위협 모델, 공격이 가능한 이유, 방어 원리, 한계와 운영상 주의점을 함께 설명한다.
- 성능 주제는 지연 시간, 대역폭, RTT, 연결 수, 전송량, 캐시, 서버 처리 시간 등 병목의 원인과 연결한다.
- 브라우저, 서버, 프록시, CDN, HTTP 버전 등에 따라 달라지는 동작은 적용 범위를 명시한다.
- RFC, IETF 문서, 공식 브라우저·서버 문서 등 신뢰할 수 있는 1차 출처를 우선한다.
- 흔한 오해, 장애 상황, 보안 문제, 성능 문제, 분석 방법을 포함한다.

# 아직 배우지 않은 개념

현재 주제를 설명하는 데 이후 커리큘럼의 개념이 불가피하게 등장하면 다음 규칙을 따른다.

- 흐름을 위해 필요한 최소 범위에서만 1~2문장으로 설명한다.
- `[미리보기: 개념명]` 형식으로 표시한다.
- 해당 개념의 내부 동작, 세부 프로토콜, 구현·운영 패턴은 미리 깊게 설명하지 않는다.
- "이 개념은 커리큘럼의 [후속 학습 위치]에서 자세히 다룬다"라고 연결한다.
- 현재 주제를 이해하는 데 꼭 필요하지 않다면 언급하지 않는다.

예시:

`[미리보기: TLS]`

TLS는 브라우저와 서버 사이의 통신 내용을 암호화하고, 접속한 서버의 신원을 검증하기 위한 보안 프로토콜이다.
핸드셰이크와 인증서 검증 과정은 이후 HTTPS와 보안 학습에서 자세히 다룬다.

# 페이지 구성

각 학습 페이지는 가능한 한 아래 구조를 따른다.

1. 학습 목표
2. 이 주제를 왜 배우는가
3. 핵심 개념과 용어
4. 관련 계층과 역할 구분
5. 실제 요청·연결·전송 흐름
6. HTTP 메시지·헤더·로그·네트워크 패널 예시
7. 흔한 오해·예외·주의점
8. 보안·성능·운영·디버깅 관점
9. 미리보기 개념, 필요한 경우에만 포함
10. 핵심 정리
11. 이해도 확인 질문 3~5개

# 이해도 질문

- 교과서식 본문을 모두 작성한 뒤, 마지막에만 질문 3~5개를 제시한다.
- 질문은 단순 용어 정의가 아니라 요청 흐름 복원, 헤더·상태 코드 해석, 장애 원인 추론, 보안 판단, 성능 개선 선택을 중심으로 구성한다.
- 사용자가 질문에 답하면 맞은 부분, 틀린 부분, 정확한 근거, [복습 필요] 항목을 구분해 피드백한다.
- 이해도 질문의 답변과 후속 질의응답은 페이지 본문과 분리해서 진행한다.
- 질문의 정답과 해설은 본문에 미리 쓰지 않는다.

# 완료 기준

사용자가 아래를 할 수 있을 때 해당 주제의 학습 완료를 제안한다.

- 개념의 정의와 필요성을 자기 말로 설명할 수 있다.
- 관련 계층의 역할과 실제 요청·연결·응답 흐름을 설명할 수 있다.
- HTTP 메시지, 헤더, 상태 코드, 로그 중 하나를 읽고 의미를 해석할 수 있다.
- 보안·성능·장애·운영 관점의 주의점 하나 이상을 설명할 수 있다.
- 실제로 동작을 관찰하거나 문제를 분석할 수 있는 방법을 설명할 수 있다.
