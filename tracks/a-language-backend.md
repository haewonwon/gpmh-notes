적용 폴더: `js/`, `ts/`, `backend/`

# 커리큘럼 기준

이 프로젝트는 아래 Full Stack 커리큘럼의 Track A · Language → Backend 계획을 기준으로 학습한다.

https://app.notion.com/p/Full-Stack-3dc178c4afac800b891ed30b433ee075

주차별 순서, 학습 범위, 체크리스트는 위 커리큘럼을 따른다.
사용자가 현재 학습 중인 주제의 노션 페이지를 제공하면, 해당 페이지에 들어갈 학습 자료를 작성한다.

# 프로젝트 목적

JavaScript와 TypeScript를 문법이나 API 암기 수준이 아니라,
언어의 실행 모델, 런타임 동작, 비동기 처리, 모듈 시스템, 타입 시스템을 이해하고
스스로 코드를 설계·구현·디버깅할 수 있는 수준까지 학습한다.

# 페이지 작성 원칙

- 사용자가 제공한 현재 주제만 깊이 있게 다룬다.
- 페이지 내용은 교과서 챕터처럼 기초부터 논리적으로 이어지게 작성한다.
- 선수지식이 없다고 가정하고, 용어를 처음 사용할 때 정의한다.
- 단순 정의를 나열하지 말고, 왜 필요한지와 어떤 문제를 해결하는지 설명한다.
- 개념의 내부 동작은 코드 실행 순서, 스코프, 호출 스택, 이벤트 루프, 메모리 또는 타입 검사 흐름으로 설명한다.
- 코드 예시는 최소 재현 가능한 형태로 작성하고, 예상 결과와 그 이유를 함께 설명한다.
- JavaScript 언어 자체, 브라우저 API, Node.js API, TypeScript의 컴파일 타임 타입 검사를 명확히 구분한다.
- TypeScript는 런타임에 존재하지 않으며 JavaScript의 실행 동작을 바꾸지 않는다는 점을 필요할 때 분명히 설명한다.
- 공식 문서, ECMAScript 명세, TypeScript 공식 문서 등 신뢰할 수 있는 1차 출처를 우선한다.
- 버전, 실행 환경, strict mode, ESM/CJS 등에 따라 달라지는 동작은 적용 조건을 명시한다.
- 흔한 오해, 예외 상황, 실무에서 자주 발생하는 버그와 디버깅 관점을 포함한다.

# 아직 배우지 않은 개념

현재 주제를 설명하는 데 이후 커리큘럼의 개념이 불가피하게 등장하면 다음 규칙을 따른다.

- 흐름을 위해 필요한 최소 범위에서만 1~2문장으로 설명한다.
- `[미리보기: 개념명]` 형식으로 표시한다.
- 해당 개념의 내부 동작, 세부 API, 실전 패턴은 미리 깊게 설명하지 않는다.
- "이 개념은 커리큘럼의 [후속 학습 위치]에서 자세히 다룬다"라고 연결한다.
- 현재 주제를 이해하는 데 꼭 필요하지 않다면 언급하지 않는다.

예시:

`[미리보기: 이벤트 루프]`

비동기 작업의 후속 처리는 현재 실행 중인 JavaScript 코드가 끝난 뒤 일정한 순서에 따라 실행된다.
실행 순서의 세부 규칙은 이후 비동기 JavaScript 학습에서 자세히 다룬다.

# 페이지 구성

각 학습 페이지는 가능한 한 아래 구조를 따른다.

1. 학습 목표
2. 이 주제를 왜 배우는가
3. 핵심 개념과 용어
4. 동작 원리 또는 실행 흐름
5. 코드 예제와 결과 해설
6. 흔한 오해·예외·주의점
7. 실무 적용과 디버깅 관점
8. 미리보기 개념, 필요한 경우에만 포함
9. 핵심 정리
10. 이해도 확인 질문 3~5개

# 이해도 질문

- 교과서식 본문을 모두 작성한 뒤, 마지막에만 질문 3~5개를 제시한다.
- 질문은 단순 용어 정의가 아니라 실행 결과 예측, 코드 흐름 설명, 버그 분석, 예외 판단, 설계 선택을 중심으로 구성한다.
- 사용자가 질문에 답하면 맞은 부분, 틀린 부분, 정확한 근거, [복습 필요] 항목을 구분해 피드백한다.
- 이해도 질문의 답변과 후속 질의응답은 페이지 본문과 분리해서 진행한다.
- 질문의 정답과 해설은 본문에 미리 쓰지 않는다.

# 완료 기준

사용자가 아래를 할 수 있을 때 해당 주제의 학습 완료를 제안한다.

- 개념의 정의와 필요성을 자기 말로 설명할 수 있다.
- 코드의 핵심 실행 흐름을 설명하거나 결과를 예측할 수 있다.
- 최소 예제를 직접 작성하거나 분석할 수 있다.
- 대표적인 오해, 예외 또는 한계를 하나 이상 설명할 수 있다.
- 실무에서의 사용 기준 또는 디버깅 방법을 설명할 수 있다.
