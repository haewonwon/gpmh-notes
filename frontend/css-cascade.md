# CSS Cascade

## CSS Cascade란?

캐스케이드(Cascade)는 같은 요소의 같은 CSS 속성에 여러 선언이 적용될 때, 어떤 선언을 우선할지 결정하는 알고리즘이다. 단순히 '마지막에 작성한 CSS가 이긴다'거나 '선택자가 구체적이면 이긴다'는 규칙만으로 설명할 수 없다.

## 1. 우선순위를 판단하는 순서

1. 관련성: 선택자가 요소와 일치하는지, @media 같은 조건이 충족되는지 확인한다.
2. 출처와 중요도: 브라우저·사용자·작성자 스타일과 !important 여부를 비교한다. 같은 출처 안에서는 캐스케이드 레이어 순서도 고려한다.
3. 명시도(Specificity): 앞선 조건에서 우선순위가 같을 때 선택자의 명시도를 비교한다.
4. 스코프 근접성: 앞선 조건과 명시도가 같다면, @scope의 스코프 루트까지 DOM 단계 수가 적은 쪽이 우선한다.
5. 선언 순서: 앞선 조건이 모두 같으면 나중에 등장한 선언이 우선한다.

중요한 점은 앞 단계에서 승패가 나면 뒤 단계의 명시도나 선언 순서로 뒤집을 수 없다는 것이다.

## 2. 출처와 중요도

레이어와 인라인 스타일의 세부 순위를 제외한 큰 틀에서, 우선순위는 낮은 쪽부터 다음과 같다.

1. 브라우저 기본 스타일의 일반 선언
2. 사용자 스타일의 일반 선언
3. 작성자 스타일의 일반 선언
4. CSS 키프레임 애니메이션이 설정하는 값
5. 작성자 스타일의 !important 선언
6. 사용자 스타일의 !important 선언
7. 브라우저 기본 스타일의 !important 선언
8. 실행 중인 CSS 트랜지션이 설정하는 값

작성자 스타일은 개발자가 작성하는 외부 CSS, style 요소, style 속성 등을 뜻한다. 사용자 스타일은 사이트 이용자가 별도로 지정하는 스타일이다. !important는 명시도를 높이는 것이 아니라 캐스케이드의 중요도 판단에 관여한다.

## 3. 명시도와 선언 순서 예제

아래는 같은 작성자 출처·중요도·레이어 조건이며 @scope를 사용하지 않는 학습용 예제다.

```html
<p id="notice" class="message">안녕하세요!</p>
```

```css
#notice { color: red; }
.message { color: blue; }
p { color: green; }
```

결과는 빨간색이다. ID 선택자의 명시도가 더 높기 때문에, 더 뒤에 작성한 p 규칙이 이기지 못한다.

```css
.message { color: blue; }
.message { color: purple; }
```

두 선언의 앞선 조건과 명시도가 같다면, 나중에 작성한 purple이 적용된다. 명시도는 캐스케이드 전체가 아니라 우선순위 판단의 한 단계다.

## 4. @layer로 스타일 그룹의 순서 정하기

```css
@layer base, components;

@layer base {
  #notice { color: red; }
}

@layer components {
  .message { color: blue; }
}
```

위 HTML에 적용하면 파란색이 된다. 같은 출처의 일반 선언에서는 나중 레이어인 components가 먼저 레이어인 base보다 우선하므로, ID 선택자의 높은 명시도로도 결과를 뒤집지 못한다.

- 일반 선언: 나중 레이어가 우선하며, 레이어 밖의 일반 스타일은 레이어 안의 일반 스타일보다 우선한다.
- !important 선언: 레이어 순서가 반전되어 먼저 선언한 레이어가 우선한다. 레이어 안의 important 선언은 레이어 밖의 important 선언보다 우선한다.
- 인라인 스타일에는 별도 우선순위가 있다. 일반 인라인 스타일은 다른 일반 작성자 스타일보다 우선하지만, 모든 종류의 선언을 이기는 것은 아니다.

## 5. 헷갈리기 쉬운 점

- '마지막 선언이 이긴다'는 앞선 우선순위가 같을 때만 맞다.
- 명시도가 높아도 더 높은 우선순위 출처·중요도·레이어를 이기지 못한다.
- !important는 항상 최강이 아니다. 실행 중인 트랜지션 값은 important 선언보다도 우선한다.
- @scope의 근접성은 단순히 선택자에 적힌 조상이 요소와 가깝다는 뜻이 아니다. 스코프 루트까지의 거리를 비교하는 별도 단계다.

## 6. 디버깅 체크리스트

1. 원하는 규칙의 선택자와 조건이 실제 요소에 적용되는가?
2. 같은 속성에 다른 출처나 !important 선언이 있는가?
3. @layer와 인라인 스타일이 우선순위에 영향을 주는가?
4. 앞선 조건이 같다면 명시도는 어느 쪽이 높은가?
5. 그래도 같다면 @scope 근접성과 선언 순서를 확인했는가?
6. 애니메이션이나 트랜지션이 해당 속성을 변경하고 있는가?

## 한 문장 정리

캐스케이드는 관련성 → 출처·중요도·레이어 → 명시도 → 스코프 근접성 → 선언 순서로 후보를 좁혀 적용할 선언을 결정한다.
